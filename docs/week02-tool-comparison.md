# Week 2 — AI Tool Comparison

## The requirement

The objective of this exercise was to develop a contact form for a Flask 3.x web application using two AI assistants: ChatGPT and Claude. The form needed to be available at the /contact route and include three fields: name, email, and message. Server-side validation was required to reject empty fields and invalid email addresses, returning an HTTP 400 status code. After successful submission, the application needed to display a confirmation message without storing the submitted information. Both AI assistants received the same prompt so their generated solutions could be compared fairly.

## Prompts used

### ChatGPT
Write a contact form for a Flask 3.x application. Give me templates/contact.html and the route
in app.py. Validate name, email and message on the server — not only in the browser. Reject
an empty field and a malformed email address, re-rendering the form with an error message and an
HTTP 400. On success show a confirmation page. **Do not use any package outside Flask and the
Python standard library.** Output each file separately with its full path.

### Claude
Write a contact form for a Flask 3.x application. Give me templates/contact.html and the route
in app.py. Validate name, email and message on the server — not only in the browser. Reject
an empty field and a malformed email address, re-rendering the form with an error message and an
HTTP 400. On success show a confirmation page. **Do not use any package outside Flask and the
Python standard library.** Output each file separately with its full path.

## Scores

| Criterion | ChatGPT | Claude |
|---|---|---|
| Correctness  | 5/5 | 5/5 |
| Code quality | 4/5 | 5/5 |
| Completeness | 4/5 | 5/5 |
| Security     | 3/5 | 4/5 |

## What each got wrong

### ChatGPT

The generated application worked correctly during the tests, but it had some limitations:

- The code did not implement maximum character limits for the name, email, or message fields.
- The validation displayed general error messages rather than identifying each field separately.
- The generated app.py included a new home route but did not preserve the existing /about route from my original project.
- The application used debug=True, which is suitable for local development but should not be enabled in production.

### Claude

The generated application also worked correctly during the tests, but some limitations were identified:

- The generated app.py did not include the existing home and /about routes from my original project.
- The application used debug=True, which should not be enabled in production.
- The confirmation page stated that the message had been received and that someone would reply, although the application did not actually send or store the message.

### Security testing limitation

Both applications accepted the test message <script>alert(1)</script> without displaying a JavaScript alert. However, neither confirmation page displayed the submitted message, so this test alone did not prove that potentially unsafe HTML would be escaped correctly.

## Which I kept, and why

I chose to keep the solution generated by Claude because it provided a more structured and complete implementation of the contact form.

Both ChatGPT and Claude passed the main functional tests, including server-side validation of empty fields and invalid email addresses, with HTTP 400 responses.

However, Claude achieved higher scores for code quality, completeness, and security. Its validation logic was organised into a separate function, making the code easier to understand and maintain. It also included maximum character limits and specific error messages for each field.

Although Claude's implementation still requires some improvements, such as disabling debug mode in production, it provides a stronger starting point for integration into my existing Flask application.

I will integrate Claude's contact form while preserving the existing home and about routes from my original project.
